# ADR-0001: Record architecture decisions

- **Status:** accepted
- **Date:** <YYYY-MM-DD>
- **Deciders:** <names>

## Context

Decisions about structure, dependencies, and boundaries get made in review
threads, chat, and conversations that leave no durable trace. Six months later
the reasoning is gone and only the consequence remains, so the decision gets
relitigated from scratch — or worse, reversed by someone who never learned what
it was protecting against.

This project is also worked on by AI agents, which start every session with no
memory. An unwritten decision does not merely fade for them; it does not exist.

## Decision

Significant architectural decisions are recorded as ADRs under `docs/adr/`, one
decision per file, numbered sequentially, indexed in `docs/adr/README.md`.

"Significant" means: it changes a boundary, adds a long-lived dependency, or
would be expensive to reverse. Library-level or reversible choices do not
qualify — an ADR per routine choice devalues the ones that matter.

ADRs are intent documents. Automated documentation tooling audits them for
broken references and reports divergence from the implementation, but never
rewrites them from code.

## Consequences

**Good.** The reasoning behind the current structure is readable without
archaeology. New contributors and agents can load the decisions instead of
inferring them. Reversing a decision requires stating why, in writing.

**Costs.** Writing one takes half an hour. The practice decays quietly if
skipped a few times in a row, so the index is reviewed during architecture
review.

**Neutral.** ADRs go stale in the sense that reality moves past them — that is
what `superseded` is for. A superseded ADR is not a defect; an unrecorded
reversal is.
